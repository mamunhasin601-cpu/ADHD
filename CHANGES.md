# Мобильный таймлайн дня

## Что внутри

- `apps/mobile/app/_layout.tsx` — НОВЫЙ. Раньше корневого layout не было вообще
  (только `app/(tabs)/_layout.tsx`), поэтому `@tanstack/react-query` был в
  зависимостях, но нигде не подключён. Добавляет `QueryClientProvider` на всё
  приложение.
- `apps/mobile/lib/timeline-config.ts` — НОВЫЙ. Диапазон часов таймлайна и размеры.
- `apps/mobile/lib/api/tasks.ts` — НОВЫЙ. React-query хуки:
  `useTasksForDate`, `useCreateTask`, `useUpdateTask`, `useToggleTask`
  (с оптимистичным апдейтом — тап должен ощущаться мгновенно).
- `apps/mobile/components/timeline/Timeline.tsx` — НОВЫЙ. Часовая шкала,
  автоскролл к "сейчас" при открытии, тап по пустому месту = быстрое создание
  с предзаполненным временем (округление до 15 мин).
- `apps/mobile/components/timeline/TaskBlock.tsx` — НОВЫЙ. Блок задачи:
  позиция/высота по `startTime`/`durationMinutes`, тап = тоггл "готово",
  долгий тап = открыть (пока заглушка).
- `apps/mobile/components/timeline/NowIndicator.tsx` — НОВЫЙ. Красная линия
  "сейчас", обновляется раз в минуту.
- `apps/mobile/app/(tabs)/today.tsx` — ЗАМЕНЯЕТ заглушку. Реальный экран:
  загрузка задач, обработка ошибок, quick-add модалка (только название,
  время — опционально).

## Допущения (проверьте, что устраивает)

1. **Диапазон таймлайна 6:00–24:00** — зашит в `timeline-config.ts`, потому что
   в модели `User` пока нет поля "время подъёма/отбоя". Когда оно появится —
   поменять два числа в конфиге, компоненты трогать не придётся.
2. **Тап по задаче = тоггл "готово"**, долгий тап = открыть. Полноценный экран
   редактирования — следующий шаг роадмапа, сейчас там `Alert` вместо реальной
   навигации.
3. **Quick-add — временная реализация** дальнейшего шага "создание/редактирование
   задач": только поле "название", без выбора цвета/подзадач/повтора. Раз шаги
   роадмапа разделены явно, полноценную форму делаем следующим шагом, а не сейчас.
4. **`includeSubTasks: true`** передаётся в query-параметрах как есть — не видел
   `GetTasksQueryDto`, чтобы свериться с точным форматом (boolean vs
   `IsBooleanString`). Если backend ждёт строку `'true'`, а не `true` —
   поправить в `lib/api/tasks.ts` одну строку.

## Проверить перед запуском

- В `apps/mobile/lib/api-client.ts` `API_BASE_URL` — на реальном устройстве/эмуляторе
  замените на актуальный IP/ngrok, `10.0.2.2` работает только в Android Emulator.
- Backend должен быть поднят (`/tasks?date=...` из прошлых шагов) — без него
  экран покажет ошибку загрузки (это уже обработано, не крашится).
- Проверить на реальном устройстве обработку тапа по пустому месту шкалы —
  вложенные `Pressable` (блоки задач) в React Native должны сами перехватывать
  тач раньше родителя, но лучше протестировать вживую, а не только в симуляторе.
