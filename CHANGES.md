# Полный экран создания/редактирования задачи

## Что внутри

- `apps/mobile/app/_layout.tsx` — ОБНОВЛЁН. Был `<Slot />`, стал `<Stack>` с двумя
  экранами: `(tabs)` (обычный) и `task-form` (модальный, `presentation: 'modal'`).
  Без этого модальное открытие формы поверх табов не заработает.
- `apps/mobile/app/task-form.tsx` — НОВЫЙ. Сам экран формы, разбор ниже.
- `apps/mobile/lib/api/tasks.ts` — ОБНОВЛЁН. Добавлены `useDeleteTask`,
  `createSubtask`, `deleteTaskById`.
- `apps/mobile/app/(tabs)/today.tsx` — ОБНОВЛЁН. Долгий тап по задаче теперь
  открывает `task-form` в режиме редактирования (был `Alert`-заглушка).
  В quick-add модалке добавлена кнопка "Подробнее →", уводящая в ту же форму
  в режиме создания с уже введённым названием/временем.

## Что в форме

- Название (обязательное), время (переключатель "без времени" / степпер часы-минуты
  с шагом 5 мин — без нативного пикера, чтобы не тянуть новую зависимость),
  длительность (чипсы 15–120 мин), цвет (8 пресетов), повтор (3 пресета RRULE),
  подзадачи (ручной ввод + два готовых шаблона), кнопка удаления в режиме
  редактирования.
- И создание, и редактирование используют одну и ту же форму — режим определяется
  наличием параметра `task` (JSON сериализованная задача передаётся через
  `useLocalSearchParams`, а не через отдельный API-запрос — задача уже есть в
  памяти из списка на экране "Сегодня").

## Сознательные упрощения (проверьте, что устраивает)

1. **Повтор — только 2 пресета** ("каждый день" / "будни"), не конструктор
   произвольных RRULE. Для MVP достаточно; полноценный конструктор — отдельная
   задача, если понадобится более гибкий повтор.
2. **Поле "с чего начать" (2-минутное правило) из ваших UX-заметок НЕ добавлено** —
   его нет в `CreateTaskDto`/схеме Prisma. Решил не дописывать поле в схему без
   вашего решения — если нужно, это отдельный маленький шаг (миграция + DTO + форма).
3. **Дата всегда "сегодня"** — как и в остальном приложении, навигации по дням
   пока нет, так что создание/редактирование считает, что происходит на сегодняшнюю
   дату (кроме случая редактирования задачи с уже существующим `startTime` — там
   день/месяц/год берутся из исходной даты задачи, меняются только часы/минуты).
4. **Подзадачи создаются последовательно после сохранения родителя** — то есть
   если создание родительской задачи прошло, а один из шагов не сохранился
   (сеть моргнула на середине списка) — родитель уже создан, а часть подзадач
   может не попасть. Для MVP это приемлемо, но при желании можно завернуть
   в одну транзакцию на бэкенде.

## Проверить перед запуском

Убедитесь, что на бэкенде реализован `DELETE /tasks/:id` (уже должен быть —
использовался в `TasksService.remove`) и что `GetTasksQueryDto`/контроллер
разрешают `parentTaskId` в `POST /tasks` (использовался с самого начала для
подзадач в `CreateTaskDto`, так что тоже должен уже работать).
