# ТЗ для Claude Code: СДВГ-планер (рабочее название "Focus")

Этот файл — полное техническое задание для локальной разработки MVP. Предназначен для того, чтобы Claude Code мог развернуть проект с нуля на локальной машине разработчика.

---

## 1. Описание продукта

**Что это:** мобильное + веб-приложение планировщика дня для людей с СДВГ (взрослая аудитория, РФ-рынок). Ключевая идея — не классический to-do список, а таймлайн-интерфейс, который визуализирует течение дня целиком (от пробуждения до сна), плюс модуль "body doubling" — виртуальный коворкинг, где пользователи видят друг друга в фокус-сессии для взаимной мотивации.

**Целевая аудитория:** русскоязычные взрослые с СДВГ или самодиагностированными симптомами, аудитория уже существующих Telegram-сообществ (25 000+ подписчиков в крупнейших каналах).

**Explicitly НЕ входит в MVP** (юридически чувствительно, ст. 10 152-ФЗ о спецкатегориях ПДн):
- Трекинг приёма лекарств
- Явная привязка функций к диагнозу СДВГ (маркетингово продукт ориентирован на аудиторию, но внутри приложения нет полей "мой диагноз", "моя таблетка" и т.п.)
- Любые медицинские опросники/тесты на СДВГ

## 2. MVP-функционал (что реализуем в первую очередь)

### Этап 1 — Планировщик (ядро продукта)
- Таймлайн-вид дня: вертикальная шкала времени от подъёма до отбоя, задачи располагаются на ней визуально (не список, а полоски на шкале)
- Создание/редактирование/удаление задач: название, время начала, длительность, цвет (свободный выбор, без премиум-ограничений)
- Подзадачи (чеклист внутри задачи)
- Повторяющиеся задачи/рутины (ежедневные, по дням недели)
- Push-уведомления: старт задачи, опционально — случайные "проверочные" уведомления (не строго по расписанию, а вразнобой — эта фича у конкурентов заявлена, но глючит; сделать надёжно)
- Виджет для домашнего экрана (текущая/следующая задача)

### Этап 2 — Body doubling (дифференцирующая фича)
- Создание "фокус-комнаты": пользователь запускает сессию совместной работы
- Видео/аудио связь между участниками комнаты (WebRTC), можно с выключенной камерой ("просто присутствие")
- Таймер сессии (например, техника Pomodoro 25/5, настраиваемая)
- Список активных публичных комнат, к которым можно присоединиться (не только по приглашению)

### Этап 3 — Контент и сообщество (после валидации MVP)
- Библиотека коротких техник КПТ на русском (текстовый контент, партнёрство с психологами из существующих Telegram-каналов)
- Не входит в первый релиз, закладываем архитектурно (модель контента в БД), но не реализуем UI сразу

## 3. Технологический стек

| Слой | Технология | Обоснование |
|---|---|---|
| Мобильное приложение | React Native + Expo | Одна кодовая база для iOS/Android, быстрый локальный запуск через Expo Go без сборки нативных бинарников на старте |
| Веб-версия | Next.js (App Router) | Тот же React, легко шарить компоненты логики с мобильным при желании (не обязательно на старте) |
| Backend/API | Node.js + NestJS (TypeScript) | Строгая типизация, встроенная модульность (удобно для последующего масштабирования: модуль задач, модуль body-doubling, модуль AI отдельно) |
| База данных | PostgreSQL 16 | Реляционная модель отлично подходит для задач/пользователей/сессий |
| ORM | Prisma | Удобные миграции, локальная разработка без боли |
| Очереди задач (напоминания) | Redis + BullMQ | Надёжная доставка push-уведомлений по расписанию, retry-логика |
| Push-уведомления | Expo Push Notifications (на старте), позже — Firebase Cloud Messaging при необходимости | Expo даёт единый API для iOS/Android без отдельной настройки APNs/FCM на старте разработки |
| WebRTC (body doubling) | **Daily.co SDK** (решение принято для MVP) | Готовая инфраструктура видео-звонков, не нужно поднимать свой signaling-сервер. Быстрее для проверки гипотезы, есть pay-as-you-go тариф. Если фича приживётся — переезд на self-hosted signaling (Socket.io + simple-peer) для экономии на масштабе и снятия вопроса с зарубежным сервисом закладывается как задача второй итерации, не MVP |
| AI-обработка (если понадобится в контентном модуле) | YandexGPT API или GigaChat API | Обязательно российские провайдеры — данные пользователей не должны уходить за рубеж (см. раздел 7) |
| Аутентификация | JWT + refresh-токены, email/телефон + код подтверждения (SMS через российского провайдера, например SMS Aero) | Без соцсети-логина через Google/Apple как единственного варианта — не все пользователи готовы давать доступ к иностранным аккаунтам |
| Контейнеризация | Docker + Docker Compose | Полностью локальный запуск всего стека одной командой |

## 4. Что установить на компьютере (пошагово)

### Обязательно для всех ОС

1. **Git** — https://git-scm.com/downloads
2. **Node.js LTS** (версия 20.x или новее) — https://nodejs.org, проверить установку: `node -v` и `npm -v`
3. **Docker Desktop** — https://www.docker.com/products/docker-desktop
   - Windows: требует включённого WSL2 (Windows Subsystem for Linux) — Docker Desktop предложит установить автоматически при первом запуске
   - Проверить установку: `docker -v` и `docker compose version`
4. **VS Code** (или другой редактор, но VS Code рекомендуется для интеграции с Claude Code) — https://code.visualstudio.com

### Для мобильной разработки

5. **Expo CLI** — устанавливается через npm, отдельно скачивать не нужно: `npm install -g expo-cli` (или используется через `npx expo` без глобальной установки — предпочтительнее, чтобы не было конфликтов версий)
6. **Expo Go** (приложение на телефон) — скачать из App Store или Google Play / RuStore на свой физический телефон для тестирования без сборки
7. **Android Studio** (нужен для Android-эмулятора, даже если тестируете на реальном телефоне — полезно иметь) — https://developer.android.com/studio
   - После установки: через Android Studio → Device Manager создать виртуальное устройство (AVD)
   - Установить Android SDK, Android SDK Platform-Tools
   - Добавить переменные окружения `ANDROID_HOME` и добавить `platform-tools` в `PATH`
8. **Xcode** (только для Mac, только если нужен iOS-симулятор) — из Mac App Store
   - После установки: `xcode-select --install` в терминале для command line tools
   - CocoaPods: `sudo gem install cocoapods` (нужен для нативных iOS-зависимостей)

### Для backend-разработки

9. **PostgreSQL client** (опционально, для просмотра БД глазами вместо только через код):
   - TablePlus (https://tableplus.com) или DBeaver (бесплатный, https://dbeaver.io) — оба работают на Windows/Mac/Linux
10. **Postman** или **Insomnia** — для ручного тестирования API-эндпоинтов помимо автотестов

### Проверочный чеклист после установки

```bash
node -v          # должно показать v20.x.x или новее
npm -v            # должно показать 10.x.x или новее
docker -v         # Docker version 24.x или новее
docker compose version
git --version
npx expo --version
```

```

  id, email, phone, password_hash, created_at, timezone

  id, user_id, title, start_time, duration_minutes, color, is_recurring, recurrence_rule
```

## 7. Юридические и архитектурные ограничения (обязательно к прочтению перед началом разработки)

1. **152-ФЗ, локализация ПДн:** база данных с email/телефонами/содержимым задач пользователей — физически на сервере в РФ при переходе в продакшн (для локальной разработки не актуально, но закладывать архитектуру так, чтобы прод-БД можно было развернуть на РФ-хостинге — Selectel, VK Cloud, Yandex Cloud — без переписывания кода)
2. **Не собирать медицинские данные** — см. п.1 раздела 1. Если в будущем добавится модуль трекинга симптомов — это отдельная фича с отдельным явным согласием пользователя (специальная категория ПДн, ст. 10 152-ФЗ), не делать неявно
3. **AI-провайдер** — если/когда будет добавлена AI-функциональность (например, AI-подсказки по планированию), использовать **YandexGPT или GigaChat**, не OpenAI/Claude напрямую, т.к. это исключает вопрос трансграничной передачи данных пользователей (см. предыдущий разбор в проекте)
4. **Push-уведомления через Expo** — сами уведомления не содержат чувствительных данных в теле push (только "У вас задача через 5 минут", без деталей) на случай, если пуш-провайдер закешируется где-то за рубежом

## 7.1. Интеграция Daily.co (body doubling — конкретика)

**Регистрация:** https://dashboard.daily.co/signup — бесплатный тариф на старте (лимит на количество минут/участников, уточнить актуальные условия в момент разработки, т.к. тарифы меняются).

**Как это работает на уровне кода:**
1. Backend при создании `FocusSession` делает запрос к Daily.co REST API (`POST /rooms`) — получает `room_url` для конкретной сессии
2. `room_url` сохраняется в таблице `FocusSession` (поле `room_name` из раздела 6 — переименовать в `daily_room_url` или добавить отдельное поле)
3. Мобильное приложение подключает **Daily React Native SDK** (`@daily-co/react-native-daily-js`), передаёт туда `room_url` — SDK сам показывает видео-интерфейс (превью камеры, кнопки mute/camera off, список участников)
4. Таймер сессии (Pomodoro) — это отдельная логика на вашей стороне (не часть Daily.co), просто UI-таймер поверх видео-компонента

**Переменные окружения:**
```
DAILY_API_KEY="получить в dashboard.daily.co → Developers"
DAILY_DOMAIN="ваш-поддомен.daily.co"
```

**Важный нюанс по данным:** сам видеопоток и метаданные звонка (кто с кем говорил, когда) проходят через серверы Daily.co, которые физически находятся за рубежом. Для MVP это приемлемый риск (гипотеза ещё не проверена, речь не о хранении переписки, а о живом видео без записи), но если решите **включить запись сессий** (Daily.co это умеет из коробки) — это уже полноценное хранение данных пользователей за рубежом, и здесь снова встаёт вопрос уведомления РКН, как мы обсуждали для AI-обработки. **Рекомендация: на MVP запись сессий не включать**, only live-соединение без сохранения.

**Что нужно установить дополнительно для этой части:**
```bash
cd apps/mobile
npx expo install @daily-co/react-native-daily-js @daily-co/react-native-webrtc
# Daily SDK требует нативных модулей — потребуется expo prebuild или EAS Build,
# т.к. Expo Go (управляемый workflow) не поддерживает кастомные нативные модули "из коробки"
npx expo prebuild
```

Это важный технический момент: как только подключаете Daily SDK, вы уже не можете тестировать через обычный Expo Go на телефоне — нужно собрать dev-client (`npx expo run:android` / `npx expo run:ios`) или использовать EAS Build. Планировщик (Этап 1) можно и нужно тестировать через Expo Go, а вот для Этапа 2 (body doubling) на устройстве потребуется собранная dev-версия приложения.

## 10. Тестирование

- **Backend:** Jest (встроен в NestJS по умолчанию) — unit-тесты для сервисов (особенно для логики повторяющихся задач и recurrence rules — там легко наделать багов с часовыми поясами)
- **Мобильное приложение:** Jest + React Native Testing Library для компонентов, ручное тестирование на реальном устройстве обязательно для проверки уведомлений (эмулятор не всегда корректно показывает реальное поведение push)
- **E2E:** Detox (опционально, можно отложить до после MVP)

**Особое внимание:** тесты на надёжность доставки уведомлений — именно здесь у всех конкурентов на рынке баги (уведомления перестают приходить через несколько дней). Написать интеграционный тест, который проверяет весь путь: создание задачи → постановка в очередь BullMQ → фактическая отправка → запись в `NotificationLog`.

## 11. Порядок разработки (роадмап для Claude Code)

1. Инициализировать монорепозиторий (можно через Turborepo или просто npm workspaces — не усложнять на старте)
2. Поднять Docker Compose (Postgres + Redis), настроить Prisma-схему по разделу 6
3. Backend: CRUD для User, Task, Routine — базовая аутентификация (JWT)
4. Backend: очередь напоминаний через BullMQ + интеграция с Expo Push
5. Мобильное приложение: экран таймлайна дня, создание/редактирование задач
6. Мобильное приложение: пуш-уведомления, привязка к реальному Expo-проекту
7. Backend + мобильное: модуль FocusSession (body doubling) — signaling-сервер, комнаты
8. Мобильное: UI фокус-комнат, интеграция WebRTC SDK
9. Веб-версия (после того, как мобильный MVP стабилен — не обязательно параллельно)
10. Тестирование надёжности уведомлений, полировка UX таймлайна
